Page Layout — The Anatomy of Every Page
Every page in the application follows this exact structure. Nothing more, nothing less.
Structure — top to bottom, always in this order
① PAGE HEADER
Breadcrumb · Page title · Subtitle · Action buttons (+ New, Export)
always white card, 18px title
② KPI CARDS ROW
4–6 cards, all same height, module color gradient
padding 12px 16px, icon 18px, value 20px
③ FILTER STRIP
Search · Dropdowns · Status chips — ABOVE the column header. Always.
background #fff, height 50px
④ STICKY COLUMN HEADER
position: sticky; top: 0 — NEVER scrolls away. Ever.
bg #f8faff, border-bottom 2px module-color
⑤ DATA ROWS
12px text, 10px 14px padding, collapsible if row has overflow content
hover: bg #f8faff
⑥ PAGINATION
Records count · Page buttons
bg #fff, border-top
Page Header — Clean & Consistent
One standard for ALL pages. The title size never changes. The action buttons are always on the right. Always.
❌ Problems seen across pages
• Some pages have 30px title, some 18px
• Some buttons are rounded pills, some are square
• Some pages have no subtitle at all
• Some pages put buttons on the left
• Some pages have no breadcrumb
✓ The one standard
• Title always 20px font-weight 900
• Subtitle always 12px #64748b
• Action buttons always top-right
• Primary action: filled module color
• Breadcrumb: module → page name

Sidebar Navigation — Readability Fix
The current sidebar has text that's too dark and hard to read. The fix: use rgba white at different opacities for hierarchy. Section labels are faint, inactive items are medium, active item is bright white.
❌ Current problem
• Menu items use colors that blend into the dark bg
• Section labels barely visible
• Active item not obvious enough
• Some text uses black/dark gray on dark bg
• Badge numbers hard to see
✓ Fix
• Section labels: rgba(255,255,255,0.35) — very faint
• Inactive items: rgba(255,255,255,0.65) — readable
• Hover: rgba(255,255,255,0.85)
• Active item: #c7d2fe + left border #818cf8 + bg rgba
• Never use opacity below 0.35 for any visible text

Buttons — One System, Applied Everywhere
Every button in the app uses one of these 5 types. The only variable is the module color for primary buttons.
❌ Current problems
• Some buttons are pill-shaped, some square, some have no radius
• Sizes vary wildly — some tiny, some huge
• Some buttons use emoji, some use text only, some use icons
• Hover states missing on many buttons
• No consistent spacing between multiple buttons
✓ The standard
• All buttons: border-radius 8px (not pill, not square)
• 3 sizes: sm (28px), default (36px), lg (42px)
• Primary = module color fill; Secondary = outline; Ghost = light
• All buttons: font-weight 700, gap 6px icon+text
• Spacing between buttons: always gap:8px
Button Types
← Small (sm) variants — used in table action cells
← Large (lg) variants — used in form submit rows
← Module-colored primary buttons (HR orange, Ops purple, Accounting teal)
// Primary button
background: [module color]; color: #fff; padding: 8px 18px;
border-radius: 8px; font-weight: 700; font-size: 12px; gap: 6px;

// Secondary button
background: #fff; color: [module color]; border: 1.5px solid [module color];

// Ghost button
background: transparent; color: #64748b; border: 1.5px solid #e2e8f0;

// Icon button
width: 32px; height: 32px; background: #f1f5f9; border: 1.5px solid #e2e8f0;

Form Inputs — Clean & Consistent
All input fields, selects, and textareas follow one standard. Heights, borders, focus states, labels — all identical.
❌ Current problems
• Some inputs have no border, some have thick borders
• Heights inconsistent (some 28px, some 44px)
• Labels: some bold caps, some lowercase, some missing
• Focus state missing on most inputs
• Required field (*) marking inconsistent
✓ The standard
• All inputs: height 36px, border 1.5px #e2e8f0, radius 8px
• All labels: 10px UPPERCASE 800 weight #64748b
• Focus: border-color module-color + 3px ring rgba
• Required: red * after label
• Error state: red border + error message below

Status Badges — Universal Color Code
Same color = same meaning, on every table, on every page. Never use dark backgrounds for badges — always soft pastels with dark text.
All Badge Types
Paid Active Approved Closed → Green: positive, completed, healthy
Issued Open In Progress Funds Sent → Blue: in progress, active, moving
Pending Draft Accts Pending Expiring ≤30d → Amber: waiting, needs attention
Overdue Expired Rejected Sent Back → Red: urgent, overdue, failed
Part. Issued Distributing → Purple: partial, in-between states
Cancelled Inactive On Hold → Gray: inactive, neutral, ended
