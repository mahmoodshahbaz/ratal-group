FormSubConClaim — SubCon Payment Request

QR AuthApp Only3 Gates
ACTOR: Sub-Contractor
ROUTE: /forms/subcon-claim
TABLE WRITES: subcon_claims
TABLE READS: outgoing_purchase_orders, sites, contractors, qr_tokens
Algorithm
TRIGGER: SubCon opens App → taps "Request Payment" STEP 1 — QR Authentication [G5] scan_qr() → resolve qr_tokens.contractor_id, entity_id IF token expired OR inactive → BLOCK "Invalid QR. Contact DH for new QR code." STEP 2 — PO Existence Check [G2] load_open_pos(contractor_id): SELECT * FROM outgoing_purchase_orders WHERE contractor_id = ? AND status = 'OPEN' AND balance > 0 IF result = [] → BLOCK "No open PO. Contact your DH." STEP 3 — PO Acknowledgement Check [G1] IF outgoing_purchase_orders.acknowledged = FALSE → BLOCK show_po_details() → SubCon taps "Acknowledge" UPDATE outgoing_purchase_orders SET acknowledged = TRUE, acknowledged_at = NOW() THEN allow payment request STEP 4 — PO Selection (FIFO) Auto-select: MIN(po_date) from open POs ← oldest first DH override: select by Site# in Money Request (not SubCon-selectable) STEP 5 — Form Fields (3 taps only) ① Site (auto-filled from PO) ② Amount (SAR) — validate: amount ≤ po.balance ③ Photo attachment (evidence of work done) IF amount > po.balance → WARN "Exceeds PO balance (SAR X remaining)" STEP 6 — Submit INSERT INTO subcon_claims {contractor_id, site_id, po_id, amount, photo_url, status: 'PENDING', claim_number} NOTIFY DH: In-App + Telegram "New payment request from [SubCon] — SAR [amount]" STEP 7 — DH Reviews → creates Payment Certificate [G3] ← FormMoneyRequest cannot proceed for SubCon until certificate exists
Inter-Links
REQUIRES → outgoing_purchase_orders (open PO)
REQUIRES → PO Acknowledged (G1)
TRIGGERS → DH reviews → Payment Certificate
BEFORE → FormMoneyRequest (SubCon line)
READS → FormSiteCompletion (basis for DH certification)
Templates & Notifications
Template: None at submission
After Payment: SubCon Payment Certificate ⚠️ (rebuild needed)
Notify DH: In-App + Telegram
⚠️ CODE: FormSubConClaim needs simplification to 3 taps (amount + photo only). Current form has milestones, hours, claim type — too complex for SubCon field workers. DH fills those details in Payment Certificate, not SubCon.

FormMoneyRequest — Main Payment Engine

QR AuthExcel UserFormApp + Desktop2 Bugs
ACTOR: DH / PM / Supervisor
ROUTE: /money-requests/new
TABLE WRITES: money_requests, money_request_lines
TABLE READS: employees, contractors, suppliers, sites, projects, departments, outgoing_purchase_orders, payment_certificates, subcon_claims, bank_accounts
Algorithm
TRIGGER: DH opens App / Excel UserForm → New Money Request STEP 1 — QR Authentication [G5] App: scan_qr() → resolve dh_id, entity_id Excel: VBA Login → Supabase session token STEP 2 — Header Fields Select: entity_id, department, bank_account (routing below), request_date, notes STEP 3 — Bank Account Routing (Auto) IF department = 'TISU' → default bank = 'ANB-77' IF department = 'NISU/CISU/ITSU' → default bank = 'ANB-39' ELSE → select ANB-15, ANB-18, ANB-11 DH can override per-line STEP 4 — Line Entry (multi-line) FOR EACH line: payment_type: [Employee | Contractor | Supplier | Vendor | Sub-Contractor | Local Supplier | Petty Cash] party_name, iban, expense_type (account_code), amount IF payment_type = 'Sub-Contractor': REQUIRE Site# selection → load open POs for that site + subcon [G3] CHECK payment_certificates WHERE subcon_claim_id matches AND status = 'CERTIFIED' IF no certificate → BLOCK "Create Payment Certificate first" IF amount > certificate.certified_amount → WARN "Exceeds certified amount" IF payment_type = 'Petty Cash': auto_route_bank(department) → ANB-77 or ANB-39 STEP 5 — Validate & Submit INSERT INTO money_requests {header fields} INSERT INTO money_request_lines {line_type, supplier_name, account_code, iban, amount} ⚠️ BUG: project_id and site_id NOT saved to money_request_lines STEP 6 — Notifications EMAIL Accounts: "New Money Request #MR-XXXX — SAR [total] — [payee types]" TELEGRAM: instant alert to Accounts channel IN-APP Accounts: MR appears in payment queue STEP 7 — After Accounts Pays UPDATE money_requests SET status = 'PAID', paid_at = NOW(), paid_by = accounts_id UPDATE outgoing_purchase_orders SET balance = balance - amount ← PO balance reduced GENERATE: Payment Receipt document NOTIFY DH: Email confirmation of payment NOTIFY SubCon/Employee: In-App + Telegram credit alert EXCEL USERFORM PARALLEL PATH: VBA: load_projects() ← pulls from Supabase projects VBA: load_sites(project_id) ← pulls from Supabase sites VBA: load_subcons(site_id) ← pulls from Supabase contractors DH fills amounts → VBA: submit_to_supabase(money_requests) ← Same table as App. Accounts sees one queue regardless of interface.
🐛 BUG 1: project_id exists in EMPTY_LINE state but is NOT saved to money_request_lines on insert. Fix: add project_id to lineRows map.
🐛 BUG 2: No Site# field on Money Request lines. Without Site#, system cannot auto-resolve which open PO to apply SubCon payment against.
📋 PATCH SESSION: Fix both when code patches resume.
Inter-Links
REQUIRES (SubCon) → payment_certificates (G3)
REQUIRES (SubCon) → outgoing_purchase_orders (open)
TRIGGERS → Accounts payment queue
UPDATES → outgoing_purchase_orders.balance (after payment)
PARALLEL → Excel UserForm (same backend)

Payment Certificate — SubCon Work Progress Certification

App + DesktopTemplate Rebuild Needed
ACTOR: DH (certifies), Accounts (reads)
TABLE WRITES: payment_certificates
TABLE READS: subcon_claims, outgoing_purchase_orders, site_completion_records
Algorithm
TRIGGER: DH reviews SubCon payment request → opens Payment Certificate STEP 1 — Load Context load_subcon_claim(claim_id): requested amount, site, photo load_po_status(po_id): po_value = outgoing_purchase_orders.value prev_paid = SUM(money_request_lines.amount WHERE po_id = ?) po_balance = po_value - prev_paid load_site_completion(site_id): milestone completion % STEP 2 — DH Certifies DH enters: work_progress_pct (0–100%) System calculates: earned_amount = po_value × work_progress_pct previously_paid = prev_paid (from DB) certifiable_amount = earned_amount - previously_paid this_payment = MIN(subcon_claim.amount, certifiable_amount) IF this_payment ≤ 0 → WARN "Work progress % does not support further payment" DH can override with manual certified_amount (with note) STEP 3 — Save Certificate INSERT INTO payment_certificates: {subcon_claim_id, po_id, work_progress_pct, po_value, prev_paid, certified_amount: this_payment, status: 'CERTIFIED', certified_by: dh_id, certified_at: NOW()} STEP 4 — Generate Template GENERATE: SubCon Payment Certificate DOCX (⚠️ needs rebuild) Placeholders: po_value, prev_paid, this_payment, balance_after, work_progress_pct, contractor details, site, scope, DH signature, Accounts signature store_document() → document_vault NOTIFY Accounts: Certificate ready → MR can now be submitted STEP 5 — Unlocks Money Request payment_certificates.status = 'CERTIFIED' DH can now submit FormMoneyRequest for this SubCon ← G3 now satisfied
Inter-Links
REQUIRES → subcon_claims (SubCon request)
READS → site_completion_records (progress basis)
UNLOCKS → FormMoneyRequest (SubCon line) [G3]
GENERATES → SubCon Payment Certificate DOCX ⚠️

FormOvertime — Overtime Request

QR AuthAppDH Approval
MULTIPLIERS: NORMAL/FRIDAY/HOLIDAY = 1.5× | TRAVEL = 1.0×
TABLE WRITES: overtime_records
TABLE READS: employees, sites, departments
Algorithm
TRIGGER: Employee / supervisor submits OT record STEP 1 — QR Auth [G5] STEP 2 — Form Fields employee_id, site_id, date, hours_worked ot_type: [NORMAL | FRIDAY | HOLIDAY | TRAVEL] STEP 3 — Calculate multiplier = CASE ot_type WHEN TRAVEL → 1.0 ELSE → 1.5 ot_pay = (employee.hourly_rate × multiplier × hours_worked) STEP 4 — Submit INSERT INTO overtime_records {employee_id, site_id, date, hours, ot_type, multiplier, ot_pay, status: 'PENDING'} NOTIFY DH: In-App "OT pending approval — [employee] [hours]h [type]" STEP 5 — DH Approval [G7] IF NOT approved: excluded from payroll IF approved: UPDATE status = 'APPROVED' NOTIFY Employee: In-App OT approval Included in monthly payroll run
Inter-Links
GATE → DH must approve (G7)
FEEDS → Payroll (monthly run)
REPORT → OT Summary Report by employee/site/period

🔒 Gate Decision Logic — Every Hard Block Explained
🔒 G1 — PO Acknowledgement Gate
WHEN: SubCon submits payment request CHECK: ack = outgoing_purchase_orders.acknowledged WHERE contractor_id = X IF ack = FALSE: BLOCK payment request ACTION: show PO details → SubCon taps Acknowledge UPDATE outgoing_purchase_orders SET acknowledged=TRUE, acknowledged_at=NOW() ALLOW: payment request now unlocked ELSE: proceed to G2 PURPOSE: Ensures SubCon is aware of PO terms before requesting payment. Prevents "I didn't know" disputes later. OVERRIDE: None. DH cannot bypass this on SubCon's behalf.
🔒 G2 — PO Balance & Open Status Gate
WHEN: SubCon submits payment request (after G1 passes) CHECK: open_pos = SELECT * FROM outgoing_purchase_orders WHERE contractor_id=X AND status='OPEN' AND balance > 0 IF open_pos = []: BLOCK "No open PO with remaining balance. Contact DH." EXIT FIFO SELECTION: selected_po = MIN(open_pos, key=po_date) ← oldest PO first available = selected_po.value - SUM(payments WHERE po_id=selected_po.id) AMOUNT VALIDATION: IF requested_amount > available: WARN "Amount (SAR X) exceeds PO balance (SAR Y). Reduce amount." (not a hard block — DH can certify up to available) CHECK EXHAUSTION: → triggers G4 IF available = 0 AND invoice_not_attached: BLOCK → redirect to Invoice Submission gate (G4) DH OVERRIDE: DH can select a different PO by choosing Site# in Money Request. FIFO is a suggestion, not absolute. DH sees all open POs for the SubCon.
🔒 G3 — Payment Certificate Required Before Money Request (SubCon)
WHEN: DH adds Sub-Contractor line to FormMoneyRequest CHECK: cert = SELECT * FROM payment_certificates WHERE contractor_id=X AND site_id=Y AND status='CERTIFIED' AND certified_at >= subcon_claim.submitted_at IF cert = NULL: BLOCK "Create Payment Certificate first. Certify work progress for this SubCon." SHOW LINK: → Payment Certificate screen EXIT AMOUNT CAP: IF money_request.amount > cert.certified_amount: WARN "Amount exceeds certified amount (SAR X). Cannot pay more than certified." HARD BLOCK: system prevents overpayment above certified amount PURPOSE: DH must witness site progress before authorizing payment. Prevents paying SubCon for work not yet done. Certified amount = PO_value × work_progress_pct − previously_paid OVERRIDE: DH can manually override with justified note (audit-logged).
🔒 G4 — Invoice Submission on PO Exhaustion
WHEN: SubCon attempts next payment request OR DH submits MR CHECK: total_paid = SUM(money_request_lines.amount WHERE po_id=X AND status='PAID') po_value = outgoing_purchase_orders.value IF total_paid >= po_value: invoice_present = outgoing_purchase_orders.invoice_url IS NOT NULL IF NOT invoice_present: BLOCK ALL further payment requests for this PO TRIGGER: NOTIFY SubCon: In-App + Telegram "PO fully paid. Submit invoice to proceed." TRIGGER: NOTIFY DH: In-App "PO #X exhausted. Invoice required from [SubCon]." ALLOW: DH can attach invoice on SubCon's behalf AFTER INVOICE ATTACHED: UPDATE outgoing_purchase_orders SET invoice_url=?, invoice_date=?, status='INVOICED' NOTIFY Accounts: Invoice received → ZATCA validation queue New PO can now be issued if further work needed PURPOSE: Forces formal invoicing cycle. Prevents informal payment chains. Ensures ZATCA compliance. Accounts can reconcile PO vs invoice vs payments.
🔒 G5 — QR Authentication (All Field Forms)
WHEN: Any field form URL opened (mobile/tablet) CHECK: token = URL param OR QR scan result record = SELECT * FROM qr_tokens WHERE token=? IF record = NULL: BLOCK "Invalid QR code." IF record.expiry < NOW(): BLOCK "QR code expired. Contact supervisor." IF record.active = FALSE: BLOCK "QR code deactivated." RESOLVE ACTOR: IF record.actor_type = 'EMPLOYEE' → load employee, filter forms by role IF record.actor_type = 'CONTRACTOR' → load contractor, show SubCon forms only IF record.actor_type = 'DH' → load DH, show DH forms PREFILL: entity_id, site_id, actor_id on all forms AUDIT: log token use → qr_access_log {token_id, form, timestamp, ip} MANAGEMENT: QR Manager (desktop) → create, deactivate, regenerate tokens. One token per employee/SubCon. Rotate on security events.
🔒 G6 — Payment Validation (Employee Confirms Advance)
WHEN: Cash advance issued via FormFieldPayment IMMEDIATE ACTION: NOTIFY Employee: In-App "SAR X advance issued. Confirm receipt." advance.confirmed = FALSE ← flagged on DH dashboard CHECK (24h monitoring): IF confirmed = FALSE after 24 hours: ALERT DH: "[Employee] has not confirmed SAR X advance. Follow up." Flag persists until confirmed WHEN EMPLOYEE CONFIRMS: UPDATE employee_advances: confirmed=TRUE, confirmation_photo=URL, confirmed_at=NOW() DH dashboard flag removed OVERRIDE: DH can mark confirmed manually (with audit note) if physical paper signed. PURPOSE: Creates paper trail for cash distribution. Reduces disputes. Signed voucher photo = physical evidence of receipt.
🔒 G7 — OT Approval Gate (Before Payroll)
WHEN: Monthly payroll run initiated CHECK: pending_ot = SELECT * FROM overtime_records WHERE status = 'PENDING' AND month = payroll_month IF pending_ot EXISTS: EXCLUDE from payroll calculation DH DASHBOARD: shows list of pending OT for approval DH ACTIONS PER RECORD: Approve → status='APPROVED' → included in payroll Reject → status='REJECTED' → excluded, employee notified PAYROLL FORMULA: ot_pay = hours × hourly_rate × multiplier multiplier: NORMAL/FRIDAY/HOLIDAY=1.5, TRAVEL=1.0 SAFETY: Payroll cannot close month with pending (unapproved) OT records. Forces DH to consciously approve or reject each claim.
🔒 G8 — Expense Claim DH Approval Gate
WHEN: Employee submits monthly expense claim FLOW: 1. Employee submits → status = 'SUBMITTED' 2. NOTIFY DH: Telegram + In-App 3. DH reviews each line: receipt photos, amounts, categories DH ACTION: Approve → status='APPROVED' → post_je() Dr Expense / Cr Employee Payable → GENERATE Expense Claim DOCX ✅ → NOTIFY Employee: Email + In-App → Claim VISIBLE to Accounts for payment Reject → status='REJECTED' → NOTIFY Employee: rejection reason → Employee corrects → resubmits Partial → DH edits amounts → partial approval → employee notified ACCOUNTS VISIBILITY RULE: Accounts CANNOT see claim until DH approval. Payment queue only shows approved claims. CUTOFF: Submission closed after monthly_cutoff_date. Next cycle only.
