Key Technical Point — Sticky Headers

All tables will use position: sticky; top: 0; z-index: 10 on the <thead> row, with the table wrapper set to overflow-y: auto; max-height: calc(100vh - Xpx). This keeps column headers visible at all times regardless of scroll position.

Heading Hierarchy — Section → Sub-page

Rule: The banner always shows TWO levels of heading

Level 1 (tiny uppercase label): The sidebar group name — "Finance", "Planning", "Human Resources", etc.
Level 2 (large bold title): The specific page name — "Fixed Assets", "Payroll", "Bank Reconciliation", etc.

The top-bar shows this already (via the currentNav label), but the page content area itself must also repeat it so users always know where they are.

📐 Standard Modal Size & Step Splitting Rules
All modals use the same fixed dimensions. Long forms are split into steps — never scrolled.

Modal Size Standard

Modal heightheight: 92vh
Min heightminHeight: 600px
Widthwidth: 900px (max)
Outer paddingpadding: 20px
White card offsetleft: 258, top/right/bottom: 22

Step Splitting Rules

1 screen = max 5 fields per step
If a form has more than 5 fields, split into steps.
Step names go in the left sidebar
Each step gets a clear name: "Basic Details", "Financial Terms", "Documents", "Review & Submit".
Line-item tables = their own step
Any form with a line items table (invoices, POs) puts the table in its own step to give it full width.

🚀 Implementation Priority
Recommended order for applying the new design system — global CSS changes first, then section by section.

Phase 0 — Global Changes (affects all pages, code done once)

Before touching any individual page:
1. Add a PageBanner component reusable across all pages (takes: section, title, description, color, ctaLabel, ctaClick)
2. Add a sticky header CSS class applied to all table <thead> elements
3. Add a KpiCard component (standard stat card: value, label, color)
These 3 components get built once and dropped into every page.
