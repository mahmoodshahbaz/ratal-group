Form Scrolling Rules — Design Reference

Every form in the application follows one of two scroll patterns. This document defines which is which and why.

Rule 0

Every Form Has 3 Zones — Always

Regardless of scroll type, these three zones exist on every single form page

🏷 Step 0 Banner
Module name · Big bold title · Emoji icon · Description · Step pills · START button
FULL SCREEN · ONE TIME
📌 Step Header Bar
Module color · Current step name · Step progress pills · position: sticky; top: 0
STICKY — ALWAYS VISIBLE
↕ Form Content Area
Fields, inputs, line items table
No-scroll forms: fits in this space — no overflow
Scroll forms: this area grows — scrollable
CONTENT ZONE
📌 Action Footer
Back (gray) · Save & Next / Submit (module color) · position: sticky; bottom: 0
STICKY — ALWAYS VISIBLE
Step 0 Banner appears only once when the user first opens the form. After clicking START it collapses and the user sees the step header bar instead.

📌 Sticky — Never Disappears

Step header bar and action footer are always visible. The user never loses their place or has to scroll up to find the Back or Next button.

position: sticky; top: 0; z-index: 10;

↕ Scroll-allowed Zone

Only the content area between the step header and the action footer may scroll. Nothing outside this zone ever moves.

🚫 Never Split a Form Step

If a step has too many fields to fit the content zone, split it into two steps — do not let the form scroll. The only exception is a line-items table where the user is adding rows.

📋 Table Column Headers Sticky Too

Inside a scrollable line-items table, the column header row is also sticky so the user always knows which column they are editing.

position: sticky; top: [step-header height]px;

Golden Rule

Too Many Fields? Split the Step — Never Scroll

The decision tree for handling long forms

✅ Do This

Step has 10 fields → split into Step 1 (5 fields: personal) and Step 2 (5 fields: employment).

Each step stays clean, focused, and fits the screen. The user feels clear progress.


Max 6–8 fields per step
Use step titles that describe the content

🚫 Never Do This

Put 12 fields on one step and let the user scroll through them.

This breaks the no-scroll rule, buries fields, and makes the form feel like a long document instead of a guided wizard.


Never scroll field forms
Never stack 10+ fields

⚠️ Exception — Line Items

A line-items table where the user adds rows is the only case where the content zone may scroll.

Even then: step header, table column headers, and footer remain sticky.
