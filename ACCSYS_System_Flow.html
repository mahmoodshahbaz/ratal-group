⚡ Key Transaction Flows

SubCon Payment Cycle

  1. Accounts issues Outgoing PO → Template generated
  2. SubCon gets in-app + Telegram notification
  3. SubCon acknowledges PO (Gate 1)
  4. SubCon submits Payment Request (amount + photo)
  5. DH reviews site progress (Site Completion form)
  6. DH creates Payment Certificate (certifies % done)
  7. DH submits Money Request referencing Certificate (Gate 2)
  8. Accounts pays via ANB → SubCon alert sent
  9. When PO exhausted → Invoice gate forced (Gate 3)
  10. SubCon submits invoice → ZATCA validated

Employee Expense Cycle

  1. Site Assignment links employee to site
  2. Employee submits Daily Expenses (QR auth)
  3. Employee submits Food Allowance + OT daily
  4. Month-end: Expense Claim auto-compiled from dailies
  5. DH reviews + approves Expense Claim (Gate)
  6. DH approves OT records (Gate)
  7. Accounts runs Payroll: base + OT + food allowance
  8. Auto-JE posts to ledger

Cash Advance Cycle

  1. DH issues Field Payment to employee (on-site)
  2. Auto-JE: Dr 1310 Employee Advance / Cr Petty Cash
  3. Employee receives in-app notification
  4. Employee confirms via Payment Validation form (photo of signed voucher)
  5. Advance marked confirmed in records
  6. Unconfirmed advances flagged in DH dashboard
  7. Cleared against Expense Claim at month-end

Client Billing Cycle

  1. Client issues Incoming PO to Ratal Group
  2. Recorded in system → Accounts notified
  3. Field work performed → Site Completion records
  4. Invoice raised against Incoming PO (ZATCA)
  5. Invoice sent to client (Email + Template)
  6. Payment received → matched to invoice
  7. AR updated, cash flow updated
  8. Revenue recognized in P&L

Excel UserForm Flow

  1. DH opens Excel file on desktop
  2. UserForm pulls Project No. / Site# from Supabase
  3. DH selects Site → SubCon list auto-populates
  4. DH enters payment amounts per payee
  5. VBA submits to money_requests table (same as App)
  6. Accounts sees identical MR in queue
  7. App and Excel = same backend, different interface

🔒 System Gates (Hard Blocks)

G1 — PO Acknowledgement
SubCon cannot submit payment request until they acknowledge the issued PO in-app. One-time per PO.
G2 — PO Balance Check
SubCon payment request blocked if no open PO or PO balance is zero. System shows current balance.
G3 — Payment Certificate
DH must create Payment Certificate (certified work %) before Money Request for SubCon can be submitted. MR screen shows certificate reference.
G4 — Invoice on PO Exhaustion
When cumulative payments = PO value, next payment request is blocked until formal invoice is attached. DH can attach on SubCon behalf.
G5 — QR Authentication
All field forms require QR scan for auth. No QR token = no form submission. Tokens managed via QR Manager (desktop).
G6 — Payment Validation
Cash advance not fully reconciled until employee confirms via Payment Validation form (photo of signed voucher).
G7 — OT Approval
OT submissions not included in payroll until DH approves. Unapproved OT shown as pending on DH dashboard.
G8 — Expense Claim Approval
Monthly expense claim not visible to Accounts until DH approves. Accounts cannot pay unapproved claims.
